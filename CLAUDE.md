## graphify

This project has a knowledge graph at graphify-out/ with god nodes, community structure, and cross-file relationships.

Rules:
- For codebase questions, first run `graphify query "<question>"` when graphify-out/graph.json exists. Use `graphify path "<A>" "<B>"` for relationships and `graphify explain "<concept>"` for focused concepts. These return a scoped subgraph, usually much smaller than GRAPH_REPORT.md or raw grep output.
- If graphify-out/wiki/index.md exists, use it for broad navigation instead of raw source browsing.
- Read graphify-out/GRAPH_REPORT.md only for broad architecture review or when query/path/explain do not surface enough context.
- After modifying code, run `graphify update .` to keep the graph current (AST-only, no API cost).

## graph usage notes (hand-written, not managed by graphify)

The section above is regenerated by `graphify claude install`. This one is not — edit freely.

- **Start at `graphify-out/wiki/index.md`.** Plain markdown, 30 articles, works even when the
  `graphify` command is unavailable (e.g. a Cowork task running in a cloud sandbox, where the
  Windows `graphify.EXE` cannot be invoked). Prefer it over browsing raw source.
- The graph is AST-only: 504 nodes, 1120 edges, 20 hand-named communities. Measured at
  8.4x fewer tokens per query than reading the corpus.
- `.graphifyignore` excludes `node_modules/`, `.next/`, `public/`, lockfiles, `tsconfig.json`
  and `.env*`. `.env.local` is never indexed — do not add it.
- `types/index.ts` extracts partially: `export type * from` is not parsed by the pinned
  tree-sitter TypeScript grammar. It is a barrel file, nothing meaningful is lost.
- The graph auto-rebuilds on `git commit` via the post-commit hook. Between commits it can be
  stale — run `graphify update .` after a large refactor if you need it current immediately.

## DeepSeek stays off until a GDPR transfer mechanism exists

**`ASSISTANT_MODEL_ENABLED` must remain unset or `false` in production.**

DeepSeek processes conversation content on infrastructure in China. China has no
adequacy decision, so sending personal data there requires a lawful transfer
mechanism under GDPR Chapter V — Art. 46 Standard Contractual Clauses plus a
transfer impact assessment. **None is in place.** Until one is, the assistant
runs on the deterministic offline engine in `lib/ai/demo-engine.ts`, which is
fully functional on its own.

Rules for anyone working in this repo:

- Do not set `ASSISTANT_MODEL_ENABLED=true` on the Vercel project, and do not
  change its default in `lib/env.ts` (`serverFlagEnabled` returns `false` for
  anything that is not an explicit `true`/`1`/`yes`).
- Do not remove or weaken the flag check at the top of `readDeepSeekConfig()` in
  `lib/ai/deepseek.ts`. That function is the only producer of a
  `DeepSeekConfig`, and `complete()` cannot issue its `fetch` without one, so
  that check is the single gate on the whole outbound path.
- Do not add a second path to `api.deepseek.com`, or to any other model
  provider, that bypasses `readDeepSeekConfig()`.
- Setting `DEEPSEEK_API_KEY` alone does nothing. That is intentional: a stray
  credential must never be enough to start transferring data.

Turning it on is a legal decision, not a technical one. It needs SCCs executed
with the provider, a transfer impact assessment, and the privacy notice's
section 5 rewritten to state the safeguard — see section 6 of
`../BUSINESS_PLAN.md`.
